# Anime Vanguards

Macro candidate (local, not published): Macro tab provides executor-workspace JSON files under `ViperHubNextGen/macro/AnimeVanguards`, confirmed-broadcast recording, and match playback for placement, upgrade, sell, ability, attack priority, native Auto Upgrade, Upgrade Priority and Auto Ability toggles. Playback requires a live match and matching equipped slots. The page offers wave/live-price timing, bounded retry/stop, file refresh/create/delete, and an equipped-unit comparison when HUD team data is available. Placement waits for the game's current price and sends direct placement only; it never queues phantom placement. Failed placements retry nearby X/Z offsets without editing the JSON, then follow the selected Stop/Restart/None/Return to Lobby policy. Auto-equip remains disabled. The legacy `Marco_Data` example is convertible through the game-owned `Macro/Document.luau` helper but is not silently rewritten. Local mock checks pass; live recording/playback and UI readback remain pending.
Macro controls use Record/Play toggles. Play Macro remains persistently active and never closes itself automatically: when in-game Auto Replay or Auto Next is enabled, playback replays or continues across matches indefinitely; if neither is enabled, it holds on the victory/end screen while remaining active until manually stopped. Recording clears the selected file first, saves when turned off or when a real victory end-screen arrives, discards on defeat, and resets on match restart. Playback can wait for a match and votes once for an observed Start prompt. Schema v2 stores a 12-number CFrame and omits stage/act/difficulty; v1 remains readable. Live gameplay validation remains pending.
Action indices run in recorded order. Attack priority uses the game's numeric priority state; new upgrade actions store the achieved level. Native Auto Upgrade purchases are not recorded as duplicate manual upgrades; old upgrade actions are treated as level checkpoints when Auto Upgrade is active. Redundant ability actions emitted when toggling or using native Auto Ability are suppressed during recording and skipped during playback without rewriting existing files; unconfirmed manual abilities report status and continue rather than halting playback. Existing files are normalized in memory without rewriting their JSON. Local tests pass; a full live record/play cycle remains pending.

Features: game-owned navigation skeleton (Lobby, Joiner, Game, Auto Play, Macro, Webhook, Misc). Game tab provides two-way synchronized toggles for in-game match settings: Auto Replay, Auto Next, Auto Skip Waves, and Auto Skip Start, communicating through ReplicatedStorage SharedSettingsClient and SettingsState. Joiner has one Auto Join Settings section for autosaved pause, cooldown and priority; each mode has its own collapsible section. Story, Legend Stage, Raid and Dungeon use replicated StagesData for Stage/Act selection. Regular, Daily and Weekly Challenge use the game's challenge names; Regular offers a choice of reward challenge by name. Stage-based joiners use `CreateMatch`, while Challenge joiners use `StartChallenge`. Both require a matching `MatchConfirmed` payload and local host ID before reporting confirmed. Worldline choices are read from live `WorldlinesData`; its request uses `TeleportToWorldline` after progress readback and reports a request rather than confirmed arrival. Boss Event names and the active weekly rotation are read from replicated game modules; only the active event can be requested via `StartBossEvent` with Normal/Elite. Other modes remain locked. Webhook posts Discord embeds for matches, new units, joiner, bounty, rift, equipper and auto play events (see UPDATES.md). Other tabs contain descriptions only.
Usage: start the generated local smoke harness in the lobby, choose Joiner, select Stage/Act or Challenge name, enable the relevant Auto Join toggle and turn off `Disable Auto Joiners`. The enabled joiner with highest priority is tried first. Requests retry no faster than 30 seconds; a missing server confirmation times out after 10 seconds. After a matching server confirmation and `IsHosting=true`, the Joiner sends Start once and waits for teleport. Disable the joiner to cancel an unsent Start and stop future requests; an already sent request cannot be recalled. Backup reward, ignore-act routing and reward claims are not implemented.
Auto Play tab: "Auto play - ingame" drives the game's native Auto Play (vote start, then Auto Play) and "Stage Preset Rules" pick one saved in-game Auto Play preset per mode (Story, Legend Stage, Raid, Dungeon, Boss Event, Portals, Challenge, Unit Trial, Worldline, Elemental Towers, Rift); rules apply only while Auto Play is on, are locked while it runs or Play Macro plays, and reset to None if the preset is deleted or renamed. Joiner tab: Boss Bounties joins the game's current daily bounty (data read from `BountyData` and `PlayerBountyDataHandler`) and "Change Stage in Match" lets the host switch to the highest-priority joiner target before Vote Start; Worldline skips completed worldlines. The window opts out of the game's button hover/press effects. The Joiner tab also has "Auto Join Equipper": the Team Equipper loads a chosen saved team (per joiner) before joining and before Vote Start in a match; the Macro Equipper equips the best owned unit for each unit name of a chosen macro file before joining (lobby only). ## Odyssey: Adventure (observed 2026-10-04)

Observed in a live lobby and an Adventure match; inferences are marked.

**Lobby** (`NetworkCode.LobbySpecialEventsClient`)
- State: `RequestAdventureState.Fire()` is answered through `AdventureFullStateChanged.On` with `Characters[]` (`CharacterName`, `UnlockedPowerIds`, `Loadout{Slot1,Slot2}`, `OwnsLoadoutSlot2`, `Proficiency`), `UnlockedPowerIds`, `OwnsLoadoutSlot2`, `Ascension`, `LastSelectedCharacter`. The reply can take a minute; an empty slot is nil.
- Start: `StartOdysseyAdventure.Fire({LoadoutProvided, CharacterName, Slot1, Slot2})` creates the hosted Adventure room (Start / Leave / Invite). The run begins when `LobbyMatchmakingClient.StartMatch.Fire()` is pressed in that room, like the stage modes. It did not teleport on its own.

**Match** (`GameHandler.GameData`)
- `StageType = "Odyssey"` and `SubMode = "Adventure"` (the game's own check); also `AdventureFloor`, `AdventureRoomKind` (Battle/Challenge/Elite/Shop/Treasure/Boss), `AdventureData`, `AdventureBossFloorInterval` (30), `AdventureMapSeed`, `AdventureRunSeed`, `OdysseyRoom`, `CurrentRewardPulls`.
- Remotes on `NetworkCode.GameOdysseyClient`. Fire: `SelectRoomChoose({RoomIndex})`, `CardPickPick({Choice})`, `CardPickSkip()`, `CardPickReroll()`, `CardPickExchangeBasicCards`, `CardPickSetBasicCardActive`, `BossRewardPick/Skip`, `TreasureOpenChest`, `OdysseyShopRequestStock/Purchase`, `ShopRequestState/Purchase/Reroll/RerollSection/SetLocked/Close`, `StateRunStartFamiliarPick`, `StateRunStartMemoriaPick`, `StateRunStartRequestPendingPicks`, `PickupRequest/Use`, `VoteCast`, `MapRequestSnapshot/SetCursor/PingNode`. On: `SelectRoomSelectionStarted/Ended` (Options with `Index`, `StageType`, `Stage`, `Act`), `CardPickBasicOffer` (`Options`, `RerollsRemaining`, `RerollsUsed`, `RerollCost`), `CardPickCharacterOffer` (`Options`, `AtCap`, `ExistingCards`), `BossRewardOffer`, `ShopOpened`, `OdysseyShopStockUpdated`, `StateOdysseyCoinsUpdated`, `StateRunRewardsUpdated`, `TreasureBegin...`.
- Not yet observed: the cash out remote, the shape of a card option (what `Choice` takes) and the unit reward offer. Next: read these from a run (inference: `Choice` is the option itself or its index).
